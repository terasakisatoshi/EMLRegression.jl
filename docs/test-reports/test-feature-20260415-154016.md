### result aggregation
- **Role:** Same research user, now trying to interpret the produced outputs
- **Use Case:** Run the documented summary command and inspect the aggregate CSV and formula export output
- **What they tried:** Ran `scripts/summarize_results.jl`, inspected `results/summaries/summary.csv`, and ran `scripts/export_recovered_formulas.jl`
- **Discoverability:** Good. README points directly to the right commands and directories.
- **Setup:** No extra setup was required beyond the base environment.
- **Functionality:** The summary command produced `results/summaries/summary.csv` and correctly reported how many raw JSON files were aggregated. The formula export command ran successfully, but its text output is ambiguous when multiple configs exist.
- **Expected vs Actual Outcome:** Partially matched. The data exists and is readable, but the formula export output cannot distinguish between different `config_name` and `depth` values when the same `target` and `seed` appear in multiple experiment sets.
- **Blocked steps:** None
- **Friction points:** `scripts/export_recovered_formulas.jl` only prints `target`, `seed`, and `formula`, so duplicate-looking rows appear once `results/raw/` contains multiple configs.
- **Doc suggestions:** No doc change is enough here; the script output itself should include `config_name` and likely `depth`.

## Expected vs Actual Outcome

The expected workflow was almost fully achieved:

- documented setup worked,
- tests passed,
- documented suite command produced raw artifacts,
- documented summary command produced the CSV,
- output semantics for overwrite and aggregation were clear.

The only remaining gap is in the formula export script, which loses context needed to interpret mixed-config results.

## Issues Found

- Medium: `scripts/export_recovered_formulas.jl` omits `config_name` and `depth`, so its output becomes ambiguous once `results/raw/` contains results from more than one experiment config.

## Suggestions

- Update `scripts/export_recovered_formulas.jl` to print at least `config_name`, `depth`, `target`, `seed`, and `formula`.
- If machine-readable downstream use is expected, add a CSV or JSON export mode instead of plain text only.
