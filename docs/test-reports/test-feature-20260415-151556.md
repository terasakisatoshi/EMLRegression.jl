## Per-Feature Details

### suite experiment execution
- **Role:** Research user trying to reproduce the documented Section 4.3 workflow
- **Use Case:** Run the documented depth-2 suite from the README and confirm that raw run artifacts are generated
- **What they tried:** Followed README setup, ran full test suite, then ran `scripts/run_suite.jl --config experiments/configs/must_pass_depth2.toml`
- **Discoverability:** Good. README exposes the relevant commands directly.
- **Setup:** Worked as described. `Pkg.instantiate()` completed and the full test suite passed.
- **Functionality:** The suite command completed and emitted JSON files in `results/raw/`.
- **Expected vs Actual Outcome:** Matched. The command path worked without needing undocumented fixes.
- **Blocked steps:** None
- **Friction points:** The README does not explain that repeated runs reuse the same output filenames and therefore overwrite previous artifacts for the same config-target-seed combination.
- **Doc suggestions:** Add one sentence explaining overwrite behavior for `results/raw/*.json`.

### result aggregation
- **Role:** Same research user, now trying to interpret the produced outputs
- **Use Case:** Run the documented summary command and inspect the aggregate CSV
- **What they tried:** Ran `scripts/summarize_results.jl`, inspected `results/summaries/summary.csv`, and checked formula export output
- **Discoverability:** Good. The README points directly to the right commands and directories.
- **Setup:** No extra setup was required beyond the base environment.
- **Functionality:** The summary command produced `results/summaries/summary.csv`, and the formula export script printed recovered formula placeholders.
- **Expected vs Actual Outcome:** Mostly matched. The summary file was produced and readable, but it aggregates all currently present raw JSON files, not just the suite that was most recently run.
- **Blocked steps:** None
- **Friction points:** A downstream user can easily misread the summary as representing only the latest suite run.
- **Doc suggestions:** Explicitly state that `scripts/summarize_results.jl` aggregates every JSON file currently under `results/raw/`.

## Expected vs Actual Outcome

The expected workflow was achieved:

- documented setup worked,
- tests passed,
- documented suite command produced raw artifacts,
- documented summary command produced the CSV.

The main gap is interpretability, not functionality. The docs currently underspecify how outputs accumulate and how to interpret repeated runs.

## Issues Found

- Medium: The README does not clarify that summary generation aggregates all existing raw artifacts, not just the latest suite run.
- Medium: The README does not clarify that rerunning the same config-target-seed path overwrites the corresponding raw JSON file.
- Low: The README links to detailed docs, but it could more directly point readers to the baseline report when they see all-zero success counts.

## Suggestions

- Add a short "Result semantics" subsection to the README covering overwrite behavior and aggregation scope.
- Add one line near the summary command explaining that `results/raw/` should be cleaned or archived if the user wants isolated summaries.
- Link the current baseline explanation more prominently so researchers understand why `success_count` is zero across the current baseline.
